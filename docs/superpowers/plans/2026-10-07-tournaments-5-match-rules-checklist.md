# pug-match 0.3.26: the owner's in-game checklist (Tournaments T5)

The owner stages pug-match 0.3.26 only after every row passes on a box of their choosing (not by the plan). Every expected string below was read from the plugin source at the branch head (`plugin/pug-pause.inc`, `pug-tourney.inc`, `pug-leave.inc`, `pug-gg.inc`, `pug-match.sp`). Chat colour codes are left out. `<...>` is a value that depends on timing or on the box.

## Setup

On the test box, by rcon or the server console. Short budgets so the rows are quick. `TOKEN` is any 32 lowercase hex characters (`TOKEN2` to `TOKEN5` are fresh ones for the later games). `P1` and `P2` are two players' SteamID64s (P1 is Team A, P2 is Team B). `P3` and `P4` are two more players who are connected as spectators and not rostered. `S` is a staff member with SourceMod root, also connected as a spectator.

```
sm_pug_tournament 1; sm_pug_leave_budget 0; sm_pug_end_kick 0
sm_pug_tech_limit 2; sm_pug_tech_seconds 60; sm_pug_dc_team_seconds 90
sm_pug_sub_emergency 1; sm_pug_sub_charge 0; sm_pug_admin_cooldown 60
sm_pug_pause_limit 1; sm_pug_pause_seconds 30
log on
sm_pug_match 9001 TOKEN no_mercy
sm_pug_roster "P1:a"; sm_pug_roster "P2:b"
changelevel l4d_hospital01_apartment
```

`sm_pug_match` does not load a map by itself (the site's runner does), hence the `changelevel`. Both players ready up so a round goes live before row 3.

"Log line" is what the box writes to its log (the console with `log on`), which is exactly what the site receives over UDP. Each `PUG TOKEN ...` line is signed as today. `PUGCALL` lines carry no `PUG TOKEN` prefix.

The rows run in order on the same game unless a row says otherwise; later rows depend on the budgets earlier rows spent.
